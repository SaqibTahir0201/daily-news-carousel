🤖 AI & AI AGENTS

MCP had a brutal month — and this is the one you must read

WHAT IS IT?

TERM: MCP (Model Context Protocol)

SIMPLE MEANING: A standard way for an AI app to discover and call external tools. Instead of every AI client writing custom code for every tool, a tool author writes one "MCP server" and any MCP client (Claude, Copilot, Cursor, Hermes) can use it.

REAL-WORLD EXAMPLE: You write an MCP server exposing getOrder(id) and refundOrder(id) backed by your MongoDB. Any AI assistant can now operate your store without you writing AI-specific glue.

WHAT PROBLEM DOES IT SOLVE? The N×M problem — N AI clients × M tools used to need N×M integrations. MCP makes it N+M.

HOW DOES IT WORK? JSON-RPC over either stdio (local process) or Streamable HTTP (remote server). The server advertises a list of tools with names, descriptions and JSON schemas. The model reads those descriptions, picks a tool, and the client executes the call and feeds the result back.

What actually happened in October

Between September 28 and October 5, the MCP project published ten security advisories across its Python and TypeScript SDKs. Fixed in mcp 2.2.0 (Python) and @modelcontextprotocol/sdk 1.32.0 (TypeScript). (CONFIRMED — GitHub security advisories)

The critical detail: two of the most serious fixes do nothing until you change your configuration. Upgrading alone leaves you exposed.

  • The client only refuses a rogue authorisation server if you explicitly pass issuer=.
  • The server only refuses tokens minted for a different service if you set validate_token_resource=True and return the token's audience.

Alongside that: the reference mcp-server-fetch got a default SSRF guard (version 2026.10.10) refusing private, loopback and cloud-metadata addresses. Langflow's CVE-2026-105697 (CVSS 9.9) showed an MCP stdio config could launch any command on the host. And a flaw in the OpenCode agent let a malicious MCP server execute PowerShell on Windows/WSL during sign-in — fixed in 1.18.33, with no CVE requested, so scanners won't flag vulnerable builds. (CONFIRMED — Pillar Security, The Hacker News, CVE records)

WHY ARE PEOPLE USING IT? Because it works and the whole industry adopted it — Azure MCP Server 3.0 went stable Oct 12, GitHub MCP Server 2.0.0 shipped structured outputs, and a 2026 Stacklok survey found nearly half of surveyed software companies already run MCP in production.

WHY DOES IT MATTER TO ME? Three reasons, in order:

  1. You use MCP servers right now, through Hermes. The OpenCode flaw is on Windows. You are on Windows.
  2. If you want to be an "AI agent developer", writing MCP servers in Node/TypeScript is the single most hireable version of that skill — and it's just Express with a different protocol.
  3. The security lessons here are backend lessons: OAuth audience validation, SSRF, session limits, request body caps. These are the same things that make you a better Node developer regardless of AI.

HOW COULD I USE IT IN A REAL PROJECT? Take any existing Express API you've built. Wrap three of its endpoints as MCP tools using @modelcontextprotocol/sdk. Connect it to Hermes or Claude Desktop. Now you can talk to your own database in English. That is a 90-minute project with a genuinely impressive result.

DO I NEED TO LEARN THIS NOW? Yes. This is your highest-leverage AI topic because it sits exactly on top of skills you already have.

RELEVANCE: 🟢 DIRECT  |  LEARNING PRIORITY: 🔥 HIGH  |  DEPTH: LEARN DEEPLY

The transferable idea from the Minecraft agents

TECHNOLOGY LESSON — TERM: Tool synthesis (self-generated tools)

SIMPLE MEANING: Instead of a developer hand-writing every tool an agent can call, the agent writes a small reusable function when it hits a repeated subtask, saves it, and calls it later like any other tool.

REAL-WORLD EXAMPLE: An agent doing data cleanup notices it keeps normalising phone numbers. It writes normalizePhone(str) once, stores it, and reuses it 400 times instead of asking the LLM 400 times.

WHY YOU CARE: It converts expensive, slow, non-deterministic LLM calls into cheap, fast, deterministic code. That is a backend cost-engineering pattern, and it is the one architectural idea from this story worth keeping.

Prompt caching got longer (OpenAI, Oct 20)

TERM: Prompt caching

SIMPLE MEANING: If the beginning of your prompt (system message, tool definitions, long document) is identical between calls, the provider can reuse its internal computation instead of reprocessing it — and charges you much less for those tokens.

REAL-WORLD EXAMPLE: GPT-6.1 Terra charges $1/M for normal input but $0.05/M for cached input. That's 20x cheaper. OpenAI extended the cache lifetime to 12 hours (writes cost 2.5× input price).

WHY IT MATTERS TO ME: This is the biggest, easiest cost win in any LLM app. The engineering rule is simple: put everything static at the front of your prompt and everything variable at the end. If you put the user's message first, you destroy your cache hit rate.

RELEVANCE: 🟢 DIRECT  |  LEARNING PRIORITY: 🔥 HIGH  |  DEPTH: UNDERSTAND THE BASICS (30 minutes, saves real money)

💻 MERN / JAVASCRIPT / WEB

Next.js Cache Components — the feature that had the RCE

WHAT IS CACHE COMPONENTS?

It is the model Next.js 16 introduced around the use cache directive. You mark a function, a component, or a whole file with 'use cache', and Next.js caches whatever it returns.

WHY WAS IT CREATED?

Older Next.js caching was implicit and confusing. Routes were static or dynamic based on rules you had to memorise, and people constantly got surprise behaviour. Cache Components makes caching explicit: nothing is cached unless you say so, and you say so in one obvious place.

HOW DOES IT WORK?

At build time Next.js finds the 'use cache' boundaries. At runtime it computes a cache key from the function's arguments and the props it closes over, then stores the rendered output. The rest of the page stays dynamic and streams in around the cached parts.

SIMPLE EXAMPLE:

async function ProductReviews({ productId }) {
  'use cache'
  const reviews = await db.collection('reviews').find({ productId }).toArray()
  return <ReviewList reviews={reviews} />
}

The reviews are cached per productId. The surrounding page — cart count, logged-in user, live stock — stays fresh.

WHAT EXISTING CONCEPT DOES IT REPLACE? It replaces the tangle of getStaticProps, revalidate, fetch cache options and route segment config with one explicit directive.

WHY SHOULD A NEXT.JS DEVELOPER CARE? Two reasons: it's the direction the framework is going, and this month it was the source of a critical unauthenticated RCE. If you use use cache on Next.js 16.x, you must be on 16.4.1.

SHOULD I LEARN IT? HOW DEEPLY? 🟢 DIRECT, 🔥 HIGH priority, LEARN DEEPLY. Caching is where most real-world Next.js bugs and most real-world performance wins live.

WHAT SHOULD I LEARN? 'use cache', cacheLife, cacheTag, and revalidateTag. That's the full API surface — it's small.

🏗️ TODAY'S SYSTEM DESIGN CONCEPT

CONCEPT: Idempotency (and idempotency keys)

IN ONE SENTENCE: An operation is idempotent if doing it five times produces exactly the same result as doing it once.

WHAT PROBLEM DOES IT SOLVE?

Networks lie. A client sends a request, the server processes it successfully, and then the response is lost on the way back. The client sees a timeout and retries. Without idempotency, the user is charged twice. With AI agents in the loop this gets much worse — agents retry aggressively and sometimes call the same tool twice because the first result "looked incomplete". Claude Duet's approval gate exists precisely because repeated actions are dangerous.

SIMPLE REAL-WORLD EXAMPLE:

A lift (elevator) button. Pressing it once calls the lift. Pressing it fifteen times calls the same one lift. That's idempotent. A vending machine coin slot is NOT — each coin does something new.

HOW IT WORKS:

The client generates a unique random key per intent (not per attempt) and sends it as a header: Idempotency-Key: 7f3a-91bd-.... The server, before doing the work:

  1. Tries to atomically insert that key into a store, marked "in progress".
  2. If insert succeeds → this is the first time. Do the work, save the response against the key, return it.
  3. If insert fails (key exists) → this is a retry. Return the stored response without redoing the work. If the stored state is still "in progress", return 409 Conflict.

Keys expire after 24–48 hours.

WHERE IS IT USED? Stripe's payments API, every payment gateway, message queues (to deduplicate), webhook receivers, and AI tool-calling layers.

HOW WOULD I USE IT WITH NODE/EXPRESS/MONGODB?

// Collection with a unique index + TTL:
// db.idempotency.createIndex({ key: 1 }, { unique: true })
// db.idempotency.createIndex({ createdAt: 1 }, { expireAfterSeconds: 86400 })

async function idempotent(req, res, next) {
  const key = req.get('Idempotency-Key')
  if (!key) return next()                    // optional header

  try {
    await db.collection('idempotency').insertOne({
      key, userId: req.user.id, status: 'in_progress', createdAt: new Date()
    })
  } catch (err) {
    if (err.code !== 11000) throw err        // 11000 = duplicate key
    const prior = await db.collection('idempotency').findOne({ key })
    if (prior.status === 'in_progress') return res.status(409).json({ error: 'in progress' })
    return res.status(prior.statusCode).json(prior.body)
  }

  // capture the response so we can replay it later
  const originalJson = res.json.bind(res)
  res.json = async (body) => {
    await db.collection('idempotency').updateOne(
      { key },
      { $set: { status: 'done', statusCode: res.statusCode, body } }
    )
    return originalJson(body)
  }
  next()
}

The unique index is what makes this safe — MongoDB enforces "only one writer wins" atomically, so two simultaneous retries cannot both proceed.

COMMON MISTAKE:

Generating the idempotency key on the server, or generating a new one on each retry. Both defeat the entire purpose. The key must be created once by the client, at the moment the user clicks the button, and reused for every retry of that same click. Second most common mistake: checking "does this key exist?" with a findOne and then inserting — that's a race condition. Let the unique index do the check.

WHAT I SHOULD BUILD TO LEARN IT:

A tiny Express POST /orders endpoint with the middleware above. Then hammer it: for i in 1..10; do curl -H "Idempotency-Key: abc123" ...; done. Exactly one order document should exist, and all ten responses should be identical.

🎨 CREATIVE DEVELOPMENT

TSL — Three.js Shading Language

WHAT IS IT?

TSL is a system inside Three.js that lets you write GPU shader logic in JavaScript instead of GLSL. You build a graph of small "nodes" — uv(), time, sin(), mix(), texture() — by composing JavaScript function calls. Three.js then compiles that graph down to GLSL for WebGL or WGSL for WebGPU, automatically.

WHY IS IT BECOMING IMPORTANT?

Because the web is moving from WebGL to WebGPU, and the two use completely different shader languages. GLSL code does not run on WebGPU. TSL is the escape hatch: write once, target both. Three.js's own docs state plainly that WebGPURenderer does not support ShaderMaterial, RawShaderMaterial or onBeforeCompile() — all of which are the classic ways people write custom shaders today. If you learn shaders the old way, you learn something that doesn't port.

TERM: WGSL vs GLSL

SIMPLE MEANING: GLSL is the shader language of WebGL (the current 3D web standard). WGSL is the shader language of WebGPU (the next one). Same purpose, different syntax, mutually incompatible.

TERM: Node material

SIMPLE MEANING: Instead of one big block of shader text, the material is assembled from small connected pieces, each producing a value. Like React components, but for pixels.

REAL-WORLD EXAMPLE (conceptually):

import { uv, time, sin, vec3 } from 'three/tsl'

material.colorNode = vec3(
  sin(uv().x.mul(20).add(time)).mul(0.5).add(0.5),
  0.2,
  0.8
)

Animated stripes, written in JavaScript, running on the GPU, working on both WebGL and WebGPU backends.

WHAT CAN IT DO? Everything GLSL can — plus the recent r186 release landed things like a Gaussian Splat renderer/loader built in TSL, parallax-corrected hit-point reprojection, and gaussianBlur() usable either inside a material or as a post-processing pass.

WHY DOES IT MATTER FOR CREATIVE DEVELOPMENT? Awwwards-tier sites are mostly custom shaders. TSL lowers the barrier enormously, because you can use JavaScript variables, loops, functions and your editor's autocomplete instead of a string of GLSL with no tooling.

WHY SHOULD I CARE? You are a JavaScript developer who wants to do creative dev. TSL is literally the version of shaders designed for you. And it is composable in a way that will feel familiar from React.

WHAT CAN I BUILD WITH IT? Animated gradient hero backgrounds, displaced/wobbling meshes, scroll-driven dissolve transitions, particle fields.

WHAT SHOULD I LEARN FIRST? In this exact order: (1) uv() and what UV coordinates are, (2) time and animating with sin, (3) mix() for blending two colours, (4) positionLocal for vertex displacement. Those four get you 80% of the visual effects you've admired.

RELEVANCE: 🟢 DIRECT  |  LEARNING PRIORITY: 🟠 MEDIUM  |  DEPTH: EXPERIMENT

It's MEDIUM not HIGH only because MCP + backend security are more career-urgent for you this month. But this is your long-term differentiator — very few MERN developers can also write shaders.

WHAT IS THE VULNERABILITY?

TERM: Install-time lifecycle script (preinstall / postinstall)

SIMPLE MEANING: npm lets a package declare a script that runs automatically the moment it is installed — before your code ever imports it. Just typing npm install is enough to execute a stranger's code on your laptop.

REAL-WORLD EXAMPLE: The tensorlake payload used preinstall to launch an obfuscated loader, install the Bun runtime, and run an 856 KB worm.

HOW DOES THE ATTACK WORK? (defensive view)

  1. Attacker gets write access to a legitimate repo (here: compromised maintainer identity).
  2. Adds a preinstall hook, bumps the version, lets the normal release pipeline publish it. Provenance signatures all look valid, because the poison was upstream in the source.
  3. On install, the script harvests: npm tokens, GitHub tokens, AWS credentials, SSH keys, .env files, crypto wallets, browser-stored passwords, and AI tool config files for Claude, Cursor, Kiro, Windsurf and Zed.
  4. It establishes persistence that survives removing the package, and writes .claude/settings.json and .vscode/tasks.json into your other repos so it re-runs when you open them.
  5. A "hostage token" monitor watches the stolen GitHub token. If you revoke it, it can trigger a destructive routine on your machine.

WHO IS AFFECTED? Developer laptops specifically — researchers found the loader exits when it detects CI. Anyone who ran npm install or npm update fresh (not npm ci from a lockfile) during the exposure window.

WHY SHOULD A MERN DEVELOPER CARE? Three of these facts should change your behaviour today:

  • npm ci (installs exactly from the lockfile) protected people. npm install and merged Dependabot PRs did not.
  • ignore-scripts=true in .npmrc meant the hook never fired at all.
  • It specifically targeted AI tool configs. You have those. A hijacked package doesn't need to trick a developer anymore — as the Bloom researcher put it, "it only needs to be the package an agent chooses."

HOW DO I PROTECT MY APPLICATION?

  1. Create ~/.npmrc with ignore-scripts=true. Run npm rebuild manually for the rare package that genuinely needs it (native modules like bcrypt, sharp).
  2. Use npm ci in CI and in Docker. Always COPY package-lock.json into your Dockerfile.
  3. Commit your lockfile. Never .gitignore it.
  4. Pin exact versions for anything on a 0.x line — ^0.5.140 accepts any later 0.5 patch, which is how people got hit.
  5. Do not auto-merge Dependabot/Renovate PRs. Read the diff, especially for new scripts entries.
  6. Audit your npm Trusted Publishing configs: confirm every trusted repo name still resolves to a repo you control.
  7. If you ever suspect infection: back up, remove the persistence monitor, THEN rotate credentials. Revoking first can trigger the destructive payload.

WHAT SHOULD I LEARN? npm lockfile semantics, npm audit signatures, Sigstore provenance (and its limits — it verifies who built it, not whether the source was clean), and the OWASP SSRF Prevention Cheat Sheet.

SAFE PRACTICAL LAB:

Entirely local, nothing malicious. Create a folder, run npm init -y, and add to package.json:

"scripts": { "preinstall": "node -e \"console.log('I could have read your .env right now')\"" }

Run npm install — watch it print. Now add ignore-scripts=true to a local .npmrc, delete node_modules, and run it again. Silence. You just saw and closed the exact door the Shai-Hulud worm walked through. Takes 4 minutes.

modelcontextprotocol/servers

WHAT IS IT? The official reference implementations of MCP servers, maintained by the MCP project. It hit v1.0.0 on October 11.

WHAT PROBLEM DOES IT SOLVE? It gives you working, read-the-source examples of how to expose tools to an AI model correctly.

It's a small, readable, well-commented diff that shows a real security fix in a real codebase — resolving the host before every request, re-checking every redirect hop, refusing loopback/private/link-local/metadata ranges, and deliberately putting the opt-out behind a host-side CLI flag so the model calling the tool cannot turn it off.

WHY DOES IT MATTER TO ME? That last design decision is the lesson of the whole month: safety switches belong in configuration the AI cannot reach. 🔮 WHERE TECHNOLOGY IS GOING

TREND 1: AI agents are becoming scheduled background systems, not chat windows.
WHAT THAT MEANS: Claude Duet watches your tools and messages you only when needed. Your Hermes cron wrote this file unprompted. The interface is disappearing; what remains is a trigger, a worker, a tool layer and an approval gate.
WHY IT MATTERS: This is not AI work — it's backend work. Cron, queues, workers, idempotency, permissions, audit logs. The people who build this well will be backend developers who understand LLMs, not prompt engineers.
WHAT I SHOULD LEARN: Job scheduling, queues and workers in Node, idempotency, and human-in-the-loop approval patterns.

TREND 2: The AI supply chain is the new attack surface.
WHAT THAT MEANS: The tensorlake worm specifically hunted Claude, Cursor, Windsurf and Zed config files. MCP produced ten advisories in eight days. The SlugFest researcher's line captures it: a hijacked package "only needs to be the package an agent chooses."
WHY IT MATTERS: Agents install dependencies, call URLs and execute code with your credentials, at machine speed, without a human reviewing each step. Every traditional web vulnerability now has an agent-shaped variant.
WHAT I SHOULD LEARN: Least privilege for agents (give a tool only the permissions it genuinely needs), SSRF defence at the network layer, and keeping safety switches in host configuration the model cannot modify.

TREND 3: Models are becoming interchangeable commodities.
WHAT THAT MEANS: OpenAI on Google Cloud. Anthropic on Google Cloud. OpenAI already on AWS since April. Open-weight Kimi scoring above two frontier closed models. Prices halving every few months.
WHY IT MATTERS: Betting your architecture on one provider is now a liability rather than a simplification.
WHAT I SHOULD LEARN: A provider-abstraction layer in your own code, prompt caching, and cost measurement per request.

TREND 4: The JavaScript toolchain is consolidating — and leaving JavaScript.
WHAT THAT MEANS: Deno absorbed into Cloudflare. TypeScript's compiler rewritten in Go, then ported to Rust. Node moving to one major release a year. Bundlers, linters and type checkers all becoming native binaries.
WHY IT MATTERS: Fewer runtimes, faster tools, more predictable upgrades. The churn that defined JS tooling for a decade is slowing down.
WHAT I SHOULD LEARN: Nothing new. Just stop feeling obligated to evaluate every new runtime. Stay on Node LTS and go deep instead of wide.

TREND 5: GPU programming is arriving in JavaScript properly.
WHAT THAT MEANS: WebGPU replaces WebGL, and TSL lets JavaScript developers write shaders without learning GLSL or WGSL. Three.js is building Gaussian splat rendering and post-processing on top of it.
WHY IT MATTERS: High-end visual work on the web stops requiring a graphics-programming background. WebGPU also unlocks GPU compute in the browser, not just graphics.
WHAT I SHOULD LEARN: TSL fundamentals — uv(), time, mix(), positionLocal.
